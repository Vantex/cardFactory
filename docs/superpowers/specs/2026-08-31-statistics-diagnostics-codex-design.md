# 任务 11：统计、诊断与生产资料库设计

## 目标与范围

任务 11 为现有单行星工厂增加可信的生产分析闭环：玩家可以查看多个固定时间窗口内的真实生产、消耗和净值，理解建筑或线路为什么停工，从物品反查配方和建筑，并从分析结果定位到世界中的真实建筑。

本任务继续遵循离线单机范围。统计历史是可重建缓存，不进入 `GameState`、存档 schema 或迁移链；多行星切换、跨星统计、离线结算和在线服务不属于任务 11。

## 现状问题

当前 `StatisticsSystem` 每秒扫描建筑缓冲区，把库存存量误当生产量和消耗量；`StatisticsPanel` 又自行创建第二个统计实例并在 `_process()` 中推进它。因此统计不代表真实生产事件，不按固定模拟时间采样，也无法在 UI 与模拟器之间保持单一权威来源。

诊断目前只有粗粒度 `status` 字符串，没有稳定原因码；生产目录没有物品、配方、建筑之间的正反向图，也没有循环和缺口检测。

## 方案比较

### 方案 A：继续扫描缓冲区

改动最小，但线路搬运会改变缓冲区，无法区分生产、消耗和物流；同一库存可以被重复计数。不能满足可信统计要求。

### 方案 B：把累计统计写入 `GameState`

查询简单且可以随存档恢复，但会扩大权威状态和迁移成本；长期历史会膨胀存档，并把可重建分析数据错误地变成游戏规则的一部分。

### 方案 C：模拟事件账本与有界采样窗口（采用）

生产系统记录真实配方完成量和采矿实际增量，线路系统记录真实转运量；模拟器唯一的 `StatisticsSystem` 在固定统计阶段按模拟时间封桶。UI、诊断和资料库只读取这一实例。该方案能区分生产、消耗和物流，结果与渲染帧率无关，历史有界且无需存档迁移。

## 架构

### StatisticsSystem

`StatisticsSystem` 是每个 `SimulationEngine` 独有的运行时服务：

- `record_produced(item_id, amount, building_id)` 记录真实产出；
- `record_consumed(item_id, amount, building_id)` 记录真实消耗；
- `record_transferred(item_id, amount, connection_id)` 记录真实线路转运；
- `update(delta)` 只由固定 tick 的 statistics 阶段调用；
- 每 1 秒生成一个不可变样本，最多保留 600 个样本；
- 支持 60、300、600 秒窗口，窗口不足时按实际覆盖时长计算每分钟速率；
- 暴露生产、消耗、净值、吞吐量和按建筑聚合的查询；
- 保留 `get_statistics_summary()` 兼容现有调用，但返回真实窗口速率。

`SimulationEngine` 先创建统计服务，再把它注入 `ProductionSystem` 和 `BeltSystem`。生产与线路服务不自行采样，也不访问 UI。

### ProductionDiagnostics

`ProductionDiagnostics` 是无副作用的查询服务，读取 `GameState` 与 `DataManager` 目录，返回稳定诊断条目：

- `no_recipe`：可配置生产建筑没有配方；
- `no_power`：耗电建筑供电倍率为零；
- `missing_input`：至少一种配方输入不足；
- `output_full`：至少一种配方输出无法再写入缓冲区；
- `belt_blocked`：启用线路有源货物，但目标输入缓冲区已满；
- `belt_disabled`：线路被玩家关闭。

每条结果包含 `code`、中文 `message`、`entity_id`、`building_id`、`planet_id` 和 `world_position`。同一建筑只返回当前最直接的首要原因，排序按稳定实体 ID，保证测试和 UI 不随字典顺序变化。

### RecipeGraph

`RecipeGraph` 从 `DataManager` 的物品、配方和建筑目录构建只读索引：

- 物品 → 生产配方、消费配方；
- 配方 → 支持建筑；
- 两层链与完整上游链；
- DFS 路径循环检测；
- 没有目录生产者的原料缺口；
- 基于配方 `amount / duration` 的理论每分钟速率。

图查询不读取实时库存，不修改目录，也不缓存到存档。

## UI 与交互

顶栏新增“分析”入口，打开与科技、战役和蓝图互斥的 `CodexWorkspace`。布局沿用现有 CardFactory 深色面板、青绿信息色和黄色强调色，不引入新的视觉体系。

工作区包含：

1. 统计页：搜索物品，选择 1/5/10 分钟窗口，显示生产、消耗、净值和线路吞吐；
2. 诊断页：列出真实停工建筑/线路、原因与“定位”按钮；
3. 资料库页：选择物品，查看生产/消费配方、支持建筑、两层链或完整链、缺口、循环和理论速率。

`CodexWorkspace` 发出 `locate_requested(building_id, position)`，`Main` 复用现有战役定位处理：移动相机并把该建筑设为唯一选择，从而触发真实高亮。定位不修改配方、库存、线路配置或模拟状态。任务 11 只有 `home` 行星；接口仍携带 `planet_id`，为任务 12 留出明确边界，但不实现跨星切换。

UI 不在 `_process()` 中推进统计。它读取 `GameManager.get_simulation_engine().statistics_system`，并在可见时响应 `simulation_updated`、状态替换和目录选择变化。

## 错误处理与边界

- 未知物品、配方或建筑查询返回空集合和明确缺口，不抛出运行时错误；
- 非有限、零或负记录量被忽略；
- 空历史返回零速率；
- 窗口限制在支持集合 60/300/600 秒；
- 删除后的实体不会被定位，`Main` 在修改相机前再次验证建筑存在；
- 配方循环被报告一次并停止递归，不造成无限遍历；
- 新游戏或读档会由 `GameManager` 重建 `SimulationEngine`，统计历史自然清空。

## 测试与验收

新增权威场景 `TestStatisticsCodex` 并加入统一 runner，覆盖：

- 真实配方完成与采矿增量形成生产/消耗速率；
- 相同固定模拟时间在不同帧分组下得到相同统计；
- 60/300/600 秒窗口与 600 条历史上限；
- 统计字段不进入持久化字典，替换状态后历史清空；
- 无配方、断电、缺料、输出满、线路堵塞和线路关闭的稳定原因码；
- 物品/配方/建筑正反查、两层链、完整链、缺口、理论速率和循环检测；
- 正式 UI 使用模拟器权威实例、工作区互斥、真实滚动和筛选；
- 从诊断/资料库经 Main 定位后相机与唯一选择正确，生产状态不变。
