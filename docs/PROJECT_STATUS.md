## 活跃运行树与数据流

`project.godot` 注册 `LocalSettings`、`EventBus`、`GameManager` 和 `DataManager` 四个 autoload，并以 `scenes/main/Main.tscn` 为主场景。

```text
project.godot
├─ LocalSettings → 独立设备设置（主题、字号、密度和输入偏好）
├─ DataManager → 按文件名排序加载 data/*.json → 内容引用/数值/科技循环/强制物品校验
├─ GameManager → SaveSystem → GameState → SimulationEngine
│                              ├─ PowerSystem
│                              ├─ ProductionSystem
│                              ├─ HandcraftSystem
│                              ├─ BlueprintSystem + BlueprintCodec
│                              ├─ ProgressionSystem + ObjectiveSystem
│                              ├─ BeltSystem
│                              ├─ LogisticsSystem → 站点 / 在途 / 返航
│                              ├─ DysonSphereSystem → 轨道 / 结构 / 壳面
│                              ├─ EndgameSystem → 准备 / 运行 / 胜利
│                              └─ StatisticsSystem
└─ Main.tscn → AppShell → StartMenu + SaveSlotsPanel + SettingsWorkspace
               + WorldCamera + CardRenderer + ConnectionRenderer
               + InputHandler + FactoryWorkspaceUI
                              ├─ BlueprintWorkspace
                              ├─ CampaignWorkspace + TutorialOverlay
                              ├─ CodexWorkspace（统计、诊断、资料库）
                              ├─ DysonPanel + EndgameWorkspace
                              ├─ MiniMap
                              └─ GalaxyMap → GalaxySystem / PlanetSystem
```

主场景先显示离线开始菜单和 10 个本地槽位；会话启动后才启用工厂输入与模拟。`AppShell` 只发送新游戏、继续、删除和返回意图，`GameManager` 统一协调保存、状态替换、自动保存和退出握手。`FactoryWorkspaceUI` 发出建造、手工制造、连接、批量编辑、删除、暂停和速度意图；`InputHandler` 仲裁画布操作并持有会话选择集合；两个 renderer 只读 `GameState`。`InventorySystem`、`ConstructionSystem` 和 `HandcraftSystem` 维护资源所有权与原子命令，`SimulationEngine` 以 60 Hz 固定 tick 更新权威状态。

- 燃料发电机无燃料时发电量为零并显示缺燃料状态；太阳能和风能使用显式的 0～1 发电倍率。放置基础发电机时最多从行星托盘转移 10 单位煤形成 300 秒启动燃料，拆除按剩余燃烧时间返还未用煤；正式补充燃料交互仍待后续任务接入。

## 任务 14：戴森工程

顶栏“戴森”打开正式规划工作区：选择恒星系，创建太阳帆轨道与关联层，按角度添加节点，规划壳面并查看俯视示意、材料缺口和功率估算。界面可选择当前行星发射设备，绑定目标、启停及从托盘装入耗材。三类设备施工件位于手工制造区，解锁戴森工程后使用；太阳帆、组件和火箭的阶段配方由基础制造台生产，线路可自动供帆或供火箭。

太阳帆发射后存活 600 秒；每节点消耗 2 枚火箭获得结构点，壳面至少需要 3 个节点，结构完成后每秒吸附 1 帆、每节点容量 20 帆。接收器共享本恒星系实际戴森功率，并将分配量接入各自行星电网；没有戴森工程时输出为零。规划不赠送材料，已投入结构的层不能直接删除。

schema v8 持久化每恒星系轨道、寿命批次、结构、壳面、发射配置与整数 tick；v7 补空戴森状态。固定步长先处理帆到期，再计算电力，物流之后执行发射与吸附。阶段配方和简化壳面尚非完整 DSPONLINE 内容对齐，任务 15 已接入正式终局胜利。验证与人工步骤见 [任务 14 验收](current/TASK14_ACCEPTANCE.md)。

## 任务 15：单机终局胜利

顶栏“终局”打开星际文明计划。完成戴森工程科技后，将白矩阵 30 和戴森球组件 20 汇入当前行星托盘，并使其恒星系戴森功率达到 3000 kW。确认弹窗列出来源和一次性投入，确认时重新验证条件后原子扣除材料；取消或条件改变不扣除。白矩阵阶段配方位于矩阵研究站，消耗基础矩阵 2、处理器 1、钛合金 1，6 秒产出 1。

启动后绑定来源行星，累计 60 模拟秒合格功率时间后达到单机胜利；低功率与暂停保留进度，切换行星不会借用其他星系功率或改变奖励归属。这里检查实际戴森发电能力，不从行星电网额外扣除 3000 kW。胜利不停止工厂；一次性奖励 10 白矩阵发给来源行星，库存满时保留待领，读档和重复领取不会重复发放。终局工作区展示缺口、功率、速率、预计时间、阻塞和生产定位。

schema v9 持久化阶段、来源、已投入材料、整数进度和领奖标记；v8 迁移为空准备阶段。当前门禁中的 TestDysonEndgame 包含启动原子性、真实白矩阵生产、固定步长、跨行星归属、胜利后运行、文件存档/迁移/损坏拒绝以及正式 UI 确认和定位。该阶段采用精简工业配方，尚未完成完整新游戏人工通关；详细人工步骤见 [任务 15 验收](current/TASK15_ACCEPTANCE.md)。任务 16 已接入安全离线结算与报告。

## 任务 16：安全离线结算与报告

继续槽位时，以已验证存档时间为起点，在独立状态副本上按 1×、60 Hz 精确重放；不足 1 秒直接继续，第一版最多处理 120 秒。计算按帧分段（最多 60 tick / 8 ms，单个 tick 无法中断）；原档在结果提交前保留，工厂输入与自动保存暂不启用。战役事实评估也进入固定 tick，科技、材料、在途物流、太阳帆寿命和终局共用在线模拟规则。

每槽离线事务文件记录起点、目标、摘要及唯一完成标记；结果先持久化，再通过临时档验证与备份轮换提交主档。中断后从原始起点重放或复用已准备结果，重复继续/提交不会再次应用同一时段。回拨不会降低已处理时间边界，超过上限或主动放弃的时间不会在下次继续时补领；旧裸档无可信时间戳时仅建立时间边界。

正式离线工作区显示进度，可放弃尚未进入提交阶段的收益；完成后显示真实离线、实际重放、跳过时间、产出、科技/目标变化与阻塞，写入失败可重试。报告中的产出来自模拟期间的真实统计，不直接添加估算收益。存档和事务文件用完整浮点精度写入，避免长时间累计数值的 JSON 截断导致摘要失败；GameState 保持 schema v9。详见 [任务 16 验收](current/TASK16_ACCEPTANCE.md)。下一项是任务 20 的本地存档控制与恢复体验。

## 任务 17：本机设置与桌面操作

开始菜单和工厂顶栏提供“设置”。主题、80%～200% 字号、紧凑/舒适密度、滚轮缩放方向及手柄光标速度保存到 `user://device_settings.cfg`，不进入存档；切换槽位不影响本机偏好。保存失败保留当前值。保留中文，国际化与手机适配已按用户要求取消。

桌面窗口最小 1000×600，保留顶栏、左右侧栏和建造坞；大字号采用滚动布局，焦点边框随亮/暗主题保持可见。Tab / 方向键导航界面，Enter / 手柄 A 确认，Escape / B 返回。F6 / Y 在界面和画布之间切换；画布方向键 / 左摇杆移动光标，Enter / A 选择或放置，M / 左摇杆按下移动，C / 右摇杆按下连线，Delete / X 请求删除，减号/等号或 LB/RB 缩放，右摇杆平移。鼠标和原有建造快捷键继续可用，删除不会绕过确认。

验收范围见 [任务 17 验收](current/TASK17_ACCEPTANCE.md)。测试入口为每个进程指定独立的 `--device-settings` 文件，避免读写玩家本机偏好。下一项为任务 20 的本地存档控制与恢复体验。

分辨率适配使用当前 Viewport 的可用尺寸，窗口缩放时自动重算，兼容 Godot 已有的窗口拉伸与高 DPI 坐标，不叠加读取主屏幕物理像素而重复缩放。以 1152×648 为参考，按宽高可容纳比例计算自动 UI 比例（85%～400%），再叠加用户字号；侧栏宽度有窗口占比上限，为画布保留空间。顶栏、建造坞、小地图、滚动条和画布命中区域同步更新，自动调整不写回字号偏好，也不改变 GameState。设置页显示当前可用尺寸和自动比例。
