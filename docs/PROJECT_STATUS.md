# CardFactory 项目状态

本文只记录可由当前代码和权威门禁证明的状态。运行与测试方法以根目录 [`README.md`](../README.md) 为准。

## Phase 2：已完成

Phase 2 的工厂工作区已接入主场景，并由正式测试门和无窗口主场景启动验证覆盖。Stage 0 的可信门禁、版本化权威状态和可靠本地存档入口已经完成；Stage 1 已交付固定步长、真实电力、守恒库存、基础手工制造和从原矿到基础研究矩阵的完整科学链；Stage 2 已交付高级画布/线路编辑、蓝图与实时小地图。正式教程、战役、科技推进和后续宏观系统仍未交付。

## 活跃运行树与数据流

`project.godot` 注册 `EventBus`、`GameManager` 和 `DataManager` 三个 autoload，并以 `scenes/main/Main.tscn` 为主场景。

```text
project.godot
├─ DataManager → 按文件名排序加载 data/*.json → 内容引用/数值/科技循环/强制物品校验
├─ GameManager → SaveSystem → GameState → SimulationEngine
│                              ├─ PowerSystem
│                              ├─ ProductionSystem
│                              ├─ HandcraftSystem
│                              ├─ BlueprintSystem + BlueprintCodec
│                              ├─ BeltSystem
│                              └─ StatisticsSystem
└─ Main.tscn → AppShell → StartMenu + SaveSlotsPanel
               + WorldCamera + CardRenderer + ConnectionRenderer
               + InputHandler + FactoryWorkspaceUI
                              ├─ BlueprintWorkspace
                              └─ MiniMap
```

主场景先显示离线开始菜单和 10 个本地槽位；会话启动后才启用工厂输入与模拟。`AppShell` 只发送新游戏、继续、删除和返回意图，`GameManager` 统一协调保存、状态替换、自动保存和退出握手。`FactoryWorkspaceUI` 发出建造、手工制造、连接、批量编辑、删除、暂停和速度意图；`InputHandler` 仲裁画布操作并持有会话选择集合；两个 renderer 只读 `GameState`。`InventorySystem`、`ConstructionSystem` 和 `HandcraftSystem` 维护资源所有权与原子命令，`SimulationEngine` 以 60 Hz 固定 tick 更新权威状态。

## 已验证能力

权威门禁：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\run_tests.ps1
```

它先自动执行一次无窗口编辑器导入，再顺序运行 `TestBaseline`、`TestFactoryWorkspace`、`TestStatePersistence`、`TestSimulationCore`、`TestInventoryConstruction`、`TestAdvancedCanvas` 与 `TestBlueprints`，要求各自唯一的成功标记。门禁会在 Godot 非零退出、`SCRIPT ERROR`、`Parse Error`、失败标记、成功标记缺失/重复、ObjectDB 泄漏或资源仍被占用时失败。全新检出不再需要人工预热全局脚本类缓存。

工作区测试覆盖：

- 新游戏拥有矿机、熔炉、制造台、发电机和矩阵研究站各一件的施工套装；成功放置只消耗对应建筑件，未知建筑、缺少建筑件和任意 232×144 卡片矩形重叠均不改变状态，边缘相邻合法。
- 行星库存、施工库存和光标载荷有明确容量、非负与唯一所有权约束；拆除建筑会先预检全部返还容量，再统一返还施工件和输入/输出缓存并级联删除连接，失败不改变任何状态。
- 基础手工配方支持 1～99 批量需求、缺料与上游配方预览；排队时一次性保留整批输入，持久队列按固定 tick 推进并在暂停、保存和加载后继续，不重复或丢失产物。
- 矿机到熔炉自动选择可兼容配方；自连接、重复连接和配方不兼容连接被拒绝；删除建筑级联删除连接。
- 主场景包含 `WorldCamera`、`CardRenderer`、`ConnectionRenderer`、`InputHandler` 和 `FactoryWorkspaceUI`，不再挂载旧 `HUD` 或 `BuildingPanel`。
- 顶栏动态显示运行/暂停、速度、电力、施工件、数量和时间；资源栏显示行星托盘、光标载荷、手工队列、生产概况和操作提示；空闲检查器提供手工配方，建筑检查器显示状态、进度、电力、缓冲区、设备配方以及连接/删除动作；建造坞显示已有/需要数量、缺料原因、快捷键和当前模式。
- 失败放置及自连接、重复连接、配方不兼容等原因会以中文短时通知显示；通知自动隐藏且不参与 UI 命中测试，其他 UI 面板仍阻止输入穿透到画布。
- 连接手势在非单位 Viewport、CanvasLayer 和世界 CanvasItem 变换下分别换算 UI 与世界坐标；在 Inspector 内松开会取消，不会误命中其下方建筑并报告“连接已存在”。
- 画布支持 Q/W/E/R/T 放置、同次按压的左键选择/拖动、输出端口按下后在输入端口释放完成连接、右键/中键平移、滚轮缩放、`Escape` 取消、`Delete` 删除、`Space` 暂停与 `1` / `2` / `3` 速度切换。
- 连接以 `enabled` 保存持久运输许可，以 `active` 表示当前帧实际物流；禁用连接不运输，启用但无货物的连接保持非活动。
- 画布选择属于会话状态，支持 Ctrl 增减和从空白开始的正向/反向框选；建筑批量移动和确认删除会完整预检并原子提交，任一锁定、重叠或退款容量失败均不产生部分结果。
- 线路支持 Mk.I/II/III、1～4 并联、1/2/4 堆叠、优先级、路线/手动偏移、监控和启停；模拟吞吐使用“等级额定值 × 并联 × 堆叠”，竞争线路按优先级及稳定 ID 顺序处理。
- 单选检查器显示完整建筑或线路配置；纯建筑和纯线路多选只提供共同命令。整网同步/升级要求显式选择模板线路，按真实连通端点报告成功、跳过和失败原因，并保留当前流量、累计统计与在途货物。
- 蓝图 v1 只保存版本、相对位置、建筑类型/生产配置和内部线路的持久配置，不保存运行中库存、进度、稳定 ID、选中态、节点引用、在途货物或累计统计；受限 JSON 导入校验字段类型、数量、坐标、文本长度与引用，导入本身不会部署。
- 蓝图部署会先构造完整目标图与总成本，再统一验证空间、科技解锁、采集/配方输出、线路端点兼容性、重复边和施工库存；任一失败不创建实体、不扣物资、不消耗稳定 ID。提交阶段故障会完整恢复建筑、线路、库存和下一个 ID。
- 正式 Main 的 Inspector 提供默认收起的蓝图入口；工作台支持捕获、顺逆时针旋转、镜像、变换后 footprint 预览、剪贴板导入导出和部署到相机。工作台与小地图纳入统一 UI 命中测试，连接或框选释放不会穿透到其后的世界对象。
- 小地图读取实时相机和由当前 `GameState` 派生的空间索引，动态覆盖远端及负坐标建筑，点击/拖动可移动相机；区域和书签只改变绘制与导航，不进入生产、库存或存档规则。
- 矿机可在检查器切换铁矿、铜矿、煤和石料采集目标；权威模拟会运行铁/铜原矿、三类冶炼、两类组装和矩阵编码的完整连接图，最终产出基础研究矩阵。
- 当前目录包含 39 个物品、30 个建筑、22 个配方和 3 项科技。采集、燃料、设备缓存、速度、多输入、多输出及副产物由 JSON 驱动；每项副产物都会进入生产完成事件。完整映射见[内容清单](current/CONTENT_CATALOG.md)。
- `DataManager` 拒绝重复 ID、缺失引用、非法数量/时间/容量、科技循环及无法制造的强制进程物品；`GameStateValidator` 另外拒绝建筑配方错配和采集器选择目录外资源。
- `GameState` 当前使用 schema v2；`GameStateCodec` 生成稳定排序的 JSON 兼容快照并恢复 `Vector2`，`GameStateValidator` 校验行星/施工/光标/手工队列及既有实体不变量，`SaveMigrationRegistry` 把旧建造点迁移为兼容施工额度并拒绝未知未来版本。状态摘要经过 JSON 写入/读回仍保持一致；`GameManager` 替换状态时会同步重建模拟服务。
- `SaveSystem` 使用临时档写入后校验、有效主档轮换备份和摘要验证完成原子槽位保存；覆盖无效槽、损坏 JSON、异常元数据、未来版本、中断临时档和损坏主档的备份恢复。加载失败不替换当前状态。
- 新游戏立即落盘，活动会话每 120 秒自动保存，返回菜单和窗口关闭前使用同一保存协调器；保存不会改变玩家暂停意图，重叠写入会被拒绝。开始菜单提供继续最近游戏，槽位页提供新建、继续、删除确认和可操作错误提示。
- 模拟以 1/60 秒固定 tick 推进；60×1/60、10×0.1 与保留并排空追赶积压的 1×1 秒输入得到相同权威摘要。每个渲染帧最多追赶 10 个 tick，超额时间不会丢失。
- 每个 tick 固定执行“电力 → 生产/采集 → 线路 → 研究边界 → 统计”。断电停止、欠电按倍率减速，恢复后沿用原生产进度；线路吞吐同时受两端供电倍率约束。
- 燃料发电机无燃料时发电量为零并显示缺燃料状态；太阳能和风能使用显式的 0～1 发电倍率。放置基础发电机时最多从行星托盘转移 10 单位煤形成 300 秒启动燃料，拆除按剩余燃烧时间返还未用煤；正式补充燃料交互仍待后续任务接入。
- `power_efficiency` 与实际 `power_output` 是可重建运行时字段，不写入规范存档；燃料剩余时间、燃料物品和可再生倍率会持久化并接受完整性校验。
- 用户已手动验收开始菜单、槽位页面、进入游戏及保存/继续流程；真实窗口布局未复现旧的 UI 重叠问题。

以下命令验证主场景能无窗口启动 120 帧；它不替代正式测试门：

```powershell
& 'C:\Program Files\Godot\Godot.exe' --headless --path . --quit-after 120 res://scenes/main/Main.tscn
```

## 已知缺口与延期范围

- 建筑缩略图仍未交付。
- 移动端布局、云存档和正式目标/胜负系统未进入活跃主场景；资源栏中的新手目标只是上下文操作引导。
- 本地存档已经交付，但当前没有单独的“立即保存”按钮；保存以新建、120 秒自动保存、返回菜单和退出握手触发。
- 云同步、云备份、云恢复、存档压缩、解压和迁移均为延期能力，当前统一返回 `ERR_UNAVAILABLE`，不会伪装成功；`PerformanceSystem` 也明确报告未启用 Worker 支持。
- 当前电力仍是单一全局电网；尚未实现电网分区、储能、发电优先级、正式燃料补给 UI 和昼夜/天气驱动的可再生波动。
- 科技定义和解锁映射已经进入数据目录，但研究资源扣除及完整推进界面尚未接入；空间站、行星、星系、戴森球及高级物流功能多数没有进入当前主场景和活跃模拟编排，部分实现只是占位或局部 API。
- `TestCompletedFeatures.gd`、`TestPhase*.gd` 等旧测试主要打印计数或结果，没有统一非零失败语义，不属于权威门禁。
