# 任务 13：行星与星际物流站

用户于 2026-09-06 授权开始实施。任务 12 的人工旅程仍未验证，不将它写成已通过。

## 设计与交付顺序

1. 用真实 Godot 回归覆盖站点库存、批量配置失败、载具转入转出、派遣与返航、断电/容量等待、保存加载与旧档迁移。
2. 站点配置和停泊载具属于建筑的 `station` 字段；飞行任务属于 GameState 的 `logistics_routes`。载具派遣时从停泊库存扣除，返航完成时归还；货物只在源站、航线、目标站三者之一。跨星系出发一次消耗两枚翘曲器，包含往返，不在读档后重复消费。
3. 固定 tick 在线路后运行物流。按需求优先级、稳定 ID、持久公平游标选择供应源；目标预留在途容量。航程按距离确定，断电停止发射和卸货，不冻结已出发飞行；满容量时等待卸货。有在途关联的站点禁止改槽物品和拆除。
4. 接入施工件制造、建造选择、物流工作台、槽位/载具配置、手动货物转移与线路自动进出。批量配置完整预检后提交。
5. 增加真实跨行星送达目标、10/50/100 站确定性夹具，运行统一门禁和主场景检查，更新权威文档。

## 边界

- 当前精简目录的施工件配方沿用任务 12 的材料基线；完整数值对齐仍属后续任务。现有翘曲器高级产线未开放建造，因此补基础矩阵 2 + 处理器 2 + 钛合金 2 的手工配方，保证跨星系可达。
- schema v7 从 v6 补空物流状态，不赠送货物或载具；旧物流文件的临时字段不构成持久契约。
- 保留用户的路线图扩展和窗口配置；仅提交本任务改动，最终留在本地 main，不推送。
- 性能夹具验证确定性和规模耗时，不以机器相关的硬毫秒阈值代替正确性。

## 实施补充

站点增加停止/恢复派遣命令，停止后现有航线继续完成，避免连续运输时无法等待到可编辑窗口。真实文件保存回归发现 JSON 整数类型影响摘要，已在保存摘要和迁移中统一归一化。正式 Inspector 的配方列表改为滚动区域以容纳新增入口。
