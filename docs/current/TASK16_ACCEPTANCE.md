# 任务 16 验收记录

规则：离线不足 1 秒直接继续；最多 120 秒，1×、60 Hz 固定 tick，不作产出估算。每帧最多 60 tick / 8 ms，单个 tick 不可抢占。超出上限及放弃的时段一并推进时间边界。旧档无时间戳不补发历史收益，时钟回拨不降低边界。

## 自动验证

新增第十二场景 `TestOfflineSettlement`，由唯一入口 `tools/run_tests.ps1` 执行。测试使用可控存档时钟和真实临时目录，覆盖：

- 10.5 秒短重放、120 秒上限、少于 1 秒的快速重开；与相同 tick 数的在线引擎对比所有持久字段。数值允许 JSON 边界不超过 1e-9 的绝对误差，整件物资和 tick 数不会出现整件/整 tick 差异。
- 燃料耗尽、有限原料、实际产出报告、科技完成、帆到期、携带真实货物的在途物流；统一战役 tick 保持完成奖励的唯一性。
- 未提交期间原槽位不变；重复提交和进程重启不重复应用；pending 中断恢复固定目标，prepared 恢复不用重新模拟。
- 结果写入失败、主档备份轮换后替换失败、主档损坏后用备份及 prepared 恢复、更新后的槽位拒绝被旧结果覆盖、事务写入失败和双份事务记录损坏。
- 时间回拨及已有完成标记后的回拨；主动放弃收益后不能重开补领；旧裸档无时间戳建立边界；删槽清理关联事务文件。
- Main 中正式继续入口、工厂输入关闭、放弃结算、报告返回工厂、提交失败显示重试、重试提交已准备结果。

存档写入改用 JSON 完整浮点精度；这是由长重放产生的可复现摘要校验失败推动的修复，仍兼容现有 schema v9 及已有摘要规则。

## 人工复现

1. 保持一条有原料和燃料的生产线，返回菜单保存，等待 5～15 秒后继续。应先出现离线进度，随后显示已保存报告，再进入工厂。
2. 等待超过 120 秒后继续，报告最多显示 120 秒模拟，剩余时间显示跳过；再次立即重开不补领被跳过的收益。
3. 在计算期间选择放弃，原始材料和进度保留，保存新的时间边界；再次继续不重新补领这一时段。
4. 在长结算中关闭程序并重开，同一事务从已验证起点或已准备结果恢复。测试注入了文件写入和替换失败；没有进行真实断电破坏文件系统的实验。
5. 在离线前让设备缺料、输出塞满或接近燃料耗尽，报告应显示真实产出和结束时阻塞。科技接近完成、帆接近到期和物流正在运输时，离线后应按实际 tick 到达边界。

自动回归不是完整新游戏人工通关、长时间人工挂机或大型工厂性能认证。120 秒是保守上限；恢复计算期间经过的现实时间不另补模拟。事务损坏或与槽位冲突时停止且保留文件，可返回菜单检查磁盘并重试；没有静默丢弃冲突记录。后续若修改存档 schema 或模拟规则，需同时核对在途离线事务兼容性。
