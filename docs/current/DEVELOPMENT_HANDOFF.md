# CardFactory 开发现状与续作指南

快照日期：2026-11-16。任务 26 已在 `d1d36907abdb5ea53a98bf00deaf785dbf52b3ae` 交付；任务 27 正在开发，尚未验收或发布。请在 **`handoff/task27-development`** 接手，其包含任务 26 历史、任务 27 当前实现、测试夹具及本文。`main` 和 `docs/task27-development-handoff` 不包含这份完整开发代码。历史测试结果标注的是当时的本地开发树，不能代替当前发布门。

## 给接手者的第一步

```powershell
git clone --branch handoff/task27-development --single-branch https://github.com/Vantex/cardFactory.git
Set-Location cardFactory
.\tools\run_tests.ps1 -Test TestParityResourceManual,TestParityResourceOutputUI,TestParityResourceJourney
node tools/test_parity_task_ownership.mjs
node tools/check_parity_recording.mjs
```

使用 Godot 4.7.2 和 Node 24；PowerShell 脚本可通过 `-GodotPath` 指定本机安装。运行既有夹具不需要源仓库；重新导出金标时，将干净的冻结 `DSPONLINE` 检出放在 CardFactory 的同级目录，保持上面的提交不变。先读根目录 `AGENTS.md`、[交接记录](HANDOFF.md) 与本文的 B1 接手顺序。参考数据及派生规则的许可见 [NOTICE](../../tests/fixtures/parity/NOTICE.md)。

规则表 `tests/fixtures/parity/rule_cases.json` 使用存储格式 2：相同断言列表保存一次，程序读取后还原各规则的原有字段。完整对比确认 1099 规则、262 已验证记录和 1,130,643 条逐 key 断言全部保留。登记、归属检查和 Godot 验证入口均读取此格式；不需 Git LFS。新格式涉及的实现指纹发生改变，后续正式登记仍须用本分支重新执行总门。

## B1 的接手顺序

1. **先关闭装机组规模的两处风险。** 静态核对：新装机写 `machine_count`，采矿吞吐会使用它；`PowerSystem` 的需电倍率与 `GameState` 的拆除退款现在都调用 `StationSystem.stack_count`，该函数只读 `station_stack_count`（默认 1）。下一步先用真实安装三台复现耗电/退款差异，再修正原生计数映射。在实际供电不足、带运输、拆除、余量及重开后检查守恒；不要用向测试直接注入功率替代组规模运行证据。该问题尚未动态复现或修复。
2. **把物资操作当作一组契约完成。** 先运行冻结源 `pickFrom*`、`dropCargoTo*`、`move*`，覆盖空仓、混装、100 单位光标上限、部分容量、满仓、锁定/错误目标、源站出库预留、物流载具及远端活动托盘。比较源机台输入、输出和光标来源。核对源版手动退回托盘超限保护，自动入库仍限容；旧原生连续量保留其合法余量。扣减和入账应原子完成，收到拒绝后库存和配置必须保持。
3. **补正式玩家入口和保存验证。** 核对 FactoryNodes 的安装/拾取，GamePanels 的资源入口与托盘操作，以及 TrayManagementDialog 的设置、丢弃、关闭。自动按钮断言覆盖结果和反馈；另记录真实鼠标键盘的焦点、关闭与输入穿透。开局旅程由实际付费命令、固定步和主档驱动，受控源夹具独立运行。
4. **在批次稳定时验收。** 接入安装及定义 runner，复跑全部受影响的场景与有界独立审查，再运行一次当前完整行为汇总；由登记器按具体断言更新 key。没有完整证据的端点保留原状态，尤其不将已有的资源领取分支推广为通用领取。此后从真实开局检查点延长 B2。

## 开发与验证方法

- 权威状态由领域系统处理；UI 转发真实命令并展示结果。比较源行为时允许内部字段映射，库存、功耗、容量、消耗、持久归属和对外反馈仍需核对。
- 从只读冻结源实际执行公开接口导出输入和结果；记录提交与加载文件哈希。用具体 key 的断言绑定夹具和本地实现，失败或证据漂移不能获得登记。不要重跑基础矩阵生成器覆盖已人工核对的映射。
- 批内汇总共享根因，先复现再一起修复，按改动范围做便宜回归；在现有 `tools/run_tests.ps1` 使用 `-Test` 选择相关场景。无参数仍为完整门。当前入口声明 65 场景；装机与定义专项还未列入。最终候选跑完整门，批内不重复做全渲染数值矩阵。
- 纯逻辑用 headless；包内首启、资源加载、实际图形、输入与保存用相应渲染器和隔离数据目录。此前同机趋势门通过，不可据此承诺大型工厂 60 FPS。
- 保留 schema v9、离线事务及历史运行证据；不改冻结参考源，不接触恢复基线工作区。当前未提交的 `project.godot` 是本地配置改动，不随本次文档归档提交。
