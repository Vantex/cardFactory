## 纯挂机与保存边界

纯挂机以真实存档时间和已积累待结算时间为预算，在独立候选状态中推进。前 1800 个精确 tick 建立三个速率观察窗口；稳定模式每十分钟重新校准，极限模式沿用已通过的投影。每桶最多三十秒真实时间，投影须通过存档、容量、矿脉、燃料和供电边界检查；配方须在十秒模拟窗口结束时保持相同周期相位，不满足时恢复精确固定步。单次计算达到三十秒预算后保存已完成进度，其余真实时间保留到后续结算。

研究队列、在途物流、量子网络、枢纽、银河出口、戴森轨道、喷涂及不满足周期约束的产线使用精确回退。这保证现有规则可继续推进，但不证明复杂工厂具有冻结源所有宏观加速能力。生产/投入和发电燃料已有投影与精确重放的比较，容量到界回退已有回归。最终复核修复了长配方校准期无产出而后续被跳过的问题：45 秒配方推进 60 秒，修复前投影 0 / 精确 1，修复后均为 1；11 秒非整窗口周期也禁止外推。

每槽独立 `.offline.pure` 事务记录起点摘要、时间和唯一收据。pending 可重放，prepared 直接恢复结果；提交前复查主档起点，写入失败保留结果，重复提交不增发收益。修改模式和保存会将等待时间归入预算一次。普通离线仍限 120 秒、1×、60 Hz，使用原事务；纯挂机没有借修改普通上限授予额外时间。

schema 继续为 v9，新领域是可选字段，未携带新字段的旧档保留原摘要。磁盘回归覆盖模式、合同、量子、采集器、黑洞、货运、戴森、空间站/枢纽、展厅、堆叠站和内容包引用。实际无限研究层数的数值类型也纳入保存规范化。

新游戏只从母星殖民地开始；完成星际物流研究后开放母恒星系另外两颗行星。已补真实实验室消耗两种矩阵各二十件的解锁、重复完成保护和保存往返，移除了提前赠送殖民地的开局逻辑。专项 `.godot/task26-colony-source-test.log` 与正式入口 `.godot/task26-colony-formal-test.log` 均通过。旧存档保留已有殖民地。开局施工库存和原生教学生产链继续兼容 CardFactory；完整源开局物料及研究施工件奖励的经济比较由任务 27 核验。

## 内容包与守恒适配

内容包仅接受数据；无脚本执行。引用、ID 冲突、循环科技、依赖版本和数值边界先检查，目录重建和注册文件读回成功后才生效；备份可恢复注册表。存档要求精确包版本与指纹，真实槽位、恢复来源、当前工厂和蓝图引用会阻止破坏性更新/停用/移除。

原生校验对损坏行采用拒绝策略，部分冻结源解析采用过滤策略；JSON 清单指纹不承诺冻结源 `undefined` 对象序列化的字节兼容。源通用 `station` 内容包类型是单物品缓存，原生映射为缓存设备，不赋予五槽星际站能力。浏览器 Worker 的缓存/合并对象协议由 Godot 串行确定性固定步承接。

跨系枢纽按物品重新检查船只和翘曲器，并共享一次结算预算，避免复现冻结源多物品重复占用舰队的缺陷。物流站增堆叠扣除施工件，缩减/拆除返还；超量库存和在途航线阻止缩减。蓝图 v1 显式拒绝多件堆叠站捕获，避免以一件施工成本复制多站；高级物流与戴森配置仍不声称蓝图 v1 完整复制。
