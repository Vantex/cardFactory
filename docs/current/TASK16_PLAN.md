# 任务 16：安全离线结算与报告

沿用 executing-plans 执行路线图。本任务不包含任务 17 产品设置。

- 使用已验证槽位的 saved_at 为起点，首次继续时固定目标时间；离线不足 1 秒不重放，最多精确重放 120 秒、1×、60 Hz。上限外和玩家放弃的时间一并标为已处理，系统时间回拨不降低时间边界。
- 结算操作持有独立 GameState 和 SimulationEngine，按帧最多 60 tick / 8 ms 分段。每 tick 保留生产、科技、帆到期、物流、终局的真实边界；战役事实评估统一进入模拟 tick。同步重放期间暂时屏蔽 EventBus，避免影响尚未安装的游戏状态。
- 每槽 .offline journal 保存起点摘要/时间、目标、tick 数和唯一 receipt。计算前持久化 pending；提交前持久化 prepared 结果与报告；随后沿用已验证临时档/备份轮换提交主档并写入 receipt。中断重启从起点重放或复用 prepared；已提交 receipt 不重复应用。
- journal 使用校验和及临时档/备份轮换；存档与 journal 不匹配时停止，不能覆盖更新后的槽位。旧已完成 journal 遇到更新的普通存档可被新结算替换。新游戏/删槽清除对应 journal。旧裸档没有可信时间时不补历史收益。
- 结算期间主场景不接受工厂操作、不自动保存，报告显示真实离线、实际重放、限制/回拨/放弃、真实产出、科技/目标变化与阻塞。完成写盘后继续游戏；失败可重试，关闭程序保留 journal。
- 增加 TestOfflineSettlement 第十二场景，验证边界等价、耗材守恒、科技/物流/帆、重启、重复提交、写入失败、回拨、放弃和正式 GameManager/UI。保持 schema v9；结算事务属于存档封装与 sidecar，不进入游戏规则状态。

长重放暴露 JSON 默认精度截断导致的临时存档摘要失败；已改为完整浮点精度写入存档和事务文件，摘要规则与 schema v9 保持兼容。验证包括真实文件替换失败及 UI 重试。
