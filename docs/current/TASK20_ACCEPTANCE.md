# 任务 20：本地保存与恢复交付记录

本轮实现路线图中任务 20 的保存协调、恢复来源选择和桌面入口，并补充手动恢复快照。游戏存档仍为 schema v9；没有修改生产数值或开启任务 21。

## 玩家入口

- 工厂顶栏「立即保存」及 Ctrl+S；顶栏状态和提示显示保存结果。
- 空闲画布按 Escape 打开暂停菜单；可继续、立即保存、创建恢复快照、管理恢复快照、保存并返回主菜单。退出失败继续保留会话。
- 开始菜单 → 本地存档 → 恢复：分别检查主档、最近有效备份、紧急恢复点和手动快照的时间、游玩时长、版本、校验结果。
- 恢复前确认具体来源；无效来源禁用。成功落盘后才安装恢复状态，恢复旧档从新的时间边界继续，过去的离线收益不重复补算。
- 手动快照可勾选后批量删除，操作须确认；不能删除最后一份有效恢复点。删除整个槽位的既有明确确认仍会删除该槽位全部文件。

## 实现与边界

保存协调器对请求持有独立状态快照，按会话内递增请求修订号串行写入；仅合并相邻相同请求，A → B → A 保持最终 A。排队返回显式 queued/durable=false，返回菜单和退出不会将排队误当成功。新游戏、手动、自动、返回、退出、恢复和离线收益提交共享协调入口。镜头先写回权威状态，再冻结请求。

主档临时文件读回、摘要与请求比对后才替换，替换后再次读回检查；写入失败不安装新会话、不清除最后有效来源。普通保存失败会尝试单独写入紧急恢复点；磁盘完全不可写时不能保证生成新文件，界面会保留失败状态。自动保存失败后重新计时，避免逐帧重试。

列表检查只读，不会因浏览而提升备份为主档。既有继续流程的自动备份回退仍保留。显式恢复尊重离线事务边界；离线日志自身损坏时返回可见错误并保留所有来源，不绕过损坏事务继续结算。

保存仍是主线程同步磁盘操作，本轮没有承诺大档异步写入或边保存边编辑。任务 19 的源项目特有选项及跨实现数值/策略一致性仍以逐项矩阵为准，不能因本轮测试通过就全部标绿；DSPONLINE 存档导入救援不属于用户授权的导入范围。
