## 运行规则字段

- `extraction.item_id`、`extraction.items`、`extraction.rate_per_minute`：定义采集器默认资源、可切换资源和速率。
- `fuel.item_id`、`fuel.burn_duration`：定义燃料发电机的燃料与单件燃烧时长。
- `input_buffer_capacity`、`output_buffer_capacity`：定义不同设备的输入、输出缓存上限。
- 配方 `inputs`、`outputs`：支持多输入、多输出和副产物；每个实际输出都会进入生产统计事件，检查器可选择下一条正式连接使用的主产物或副产物。
- 建筑 `speed`：参与固定步长生产进度，仍受实时电力效率约束。

## 启动校验门禁

`DataManager` 在加载全部 JSON 后统一拒绝以下问题：

- 跨文件重复 ID；
- 缺失物品、建筑、科技前置或解锁引用；
- 非法配方数量、持续时间、设备速度、功率、缓存和采集速率；
- 同一配方输入或输出中的重复物品；
- 科技前置循环，以及缺失名称、描述、层级、成本、效果、前置或解锁形状；
- 非法科技层级、空成本、未知成本物品、非有限/非正成本或效果、未知效果；
- 无法从目录资源节点和配方链生产的强制进程物品。

`GameStateValidator` 另外拒绝存档中的未知配方、建筑与配方类型不匹配、非法燃料和目录外采集/连接输出，以及未知研究 ID、当前项与队列重复、超过工期的进度、没有精确目录成本的投入和不合法的队列前置。schema v3→v4→v5 迁移会补齐研究字段、等待原因和可重复层数；已完成的可重复科技在 v4→v5 时初始化为第 1 层。电路与磁线圈配方保留旧 `assembler` 兼容设备映射，因此目录增加字段和施工件键后不改变 schema v2 的持久根结构，基线 v2 存档仍可直接加载。

当前可完整游玩的门槛是基础金属—电子元件—基础研究矩阵。化工、星际材料和终局建筑已有首批定义，并已获得通用运行规则支持；它们的施工入口、解锁节奏、任务目标和完整配方闭环将在后续科技、多行星和终局任务中按批次接入。每批必须继续满足启动校验和现有存档加载门禁。
