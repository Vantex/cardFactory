# CardFactory 恢复可信基线设计

> **历史归档（2026-08-23 工作区交付）：** 本设计只说明当时的可信基线范围；请以[项目状态](../../../PROJECT_STATUS.md)和[当前设计](../../../current/SINGLE_PLAYER_GAP_ANALYSIS.md)为准。

**日期：** 2026-08-23  
**状态：** 已批准  
**范围：** `card-factory`；`DSPONLINE` 只作为行为参考，不修改

## 目标

把当前能够运行局部生产链、但文档和测试不可信的 Godot 原型，恢复成可版本化、可从干净环境导入、可由自动化命令判定成败的开发基线。本阶段不增加科技、行星、戴森球、云服务或其他新玩法。

## 交付物

1. `card-factory` 拥有独立 Git 历史，接手前快照可恢复。
2. Godot 文本资源统一为 UTF-8 无 BOM，干净导入不再产生场景首行解析错误。
3. 提供单一测试入口，任何脚本错误或失败断言都产生非零退出码。
4. 修复主场景统计契约，使主场景短时运行不产生脚本错误。
5. 数据加载阶段检测重复 ID、缺失物品/建筑引用和无效配方，不再静默覆盖。
6. 只保留一份权威项目状态说明；旧审计文件明确降级为历史资料。

## 架构边界

- `DataManager` 负责加载和验证静态数据，并向调用者暴露只读查询结果。
- `GameState` 继续作为本阶段的权威运行状态；本阶段不做大规模拆分。
- `SimulationEngine` 负责编排电力、物流、生产、统计更新，其公开统计接口返回 `StatisticsSystem.get_statistics_summary()` 的稳定结构。
- 测试使用 Godot 原生脚本和真实系统对象，不以打印文字、文件存在或函数可调用作为通过条件。
- 测试运行器聚合测试结果并显式调用 `get_tree().quit(exit_code)`。

## 错误处理

- 数据错误在启动/测试阶段收集为结构化问题；测试环境将其视为失败。
- 生产运行不因单个数据文件崩溃，但必须输出包含文件和 ID 的可定位错误。
- 用户目录不可用时，存档系统返回失败并报告原因，不解引用空的 `DirAccess`。
- 测试过程中出现 GDScript 运行时错误视为门禁失败，即使旧测试打印“通过”。

## 验收标准

- Godot 4.7.2 在无旧 `.godot` 缓存的副本中完成导入。
- 主场景 headless 运行至少 120 帧，无 `SCRIPT ERROR` 和 `Parse Error`。
- 数据验证确认 4 个 JSON 文件可解析，并明确报告当前重复/坏引用，修复后为 0 项。
- 新测试入口在故意破坏统计契约时失败，恢复实现后通过。
- README 记录唯一的运行、测试、目录和进度口径。

## 非目标

- 不复刻 DSPONLINE 的全部函数、Worker、多核、账号、云档和排行榜。
- 不在本阶段完成未接入的高级系统。
- 不根据函数数量计算完成率。
