# CardFactory

其他对话接手请先读 [当前工作交接](docs/current/HANDOFF.md)，了解分支、未提交改动、验证边界和下一步。

CardFactory 是一个使用卡牌式二维界面表达工厂生产链的 Godot 原型。当前可信基线要求 **Godot 4.7.2**；其他 Godot 版本尚未验证。

## 启动与测试

在仓库根目录使用 Windows PowerShell 5.1 或 PowerShell 7。Godot 默认安装路径为 `C:\Program Files\Godot\Godot.exe`。

启动编辑器：

```powershell
& 'C:\Program Files\Godot\Godot.exe' --editor --path .
```

启动主场景：

```powershell
& 'C:\Program Files\Godot\Godot.exe' --path .
```

项目唯一的自动化测试门禁是：

全新检出或新建 worktree 后直接运行门禁：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\run_tests.ps1
```

PowerShell 7 也可用同一脚本：

```powershell
pwsh -NoProfile -File .\tools\run_tests.ps1
```

Godot 不在默认位置时，通过 `-GodotPath` 覆盖：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\run_tests.ps1 -GodotPath 'D:\Tools\Godot\Godot.exe'
```

门禁会先自动执行无窗口编辑器导入，生成资产缓存和全局脚本类缓存，再运行十六个真实 Godot 测试场景：`TestBaseline`、`TestFactoryWorkspace`、`TestStatePersistence`、`TestSimulationCore`、`TestInventoryConstruction`、`TestAdvancedCanvas`、`TestBlueprints`、`TestProgression`、`TestStatisticsCodex`、`TestGalaxyLogistics`、`TestDysonEndgame`、`TestOfflineSettlement` 、`TestProductShell` 、`TestPerformanceBudgets` 、`TestDSPOnlineParity` 与 `TestSaveRecovery`。正常通过必须同时满足：Godot 退出码为 0；每个场景的完整成功标记各出现一次；输出不包含 `SCRIPT ERROR`、`Parse Error`、对应失败标记、ObjectDB 泄漏或仍被占用的资源。引擎级 `--quit-after 600` 保证测试进程有界结束。

## 当前可玩工作区（Phase 2）

主场景从离线开始菜单进入。玩家可在 10 个本地槽位中新建或继续游戏，并在工厂画布放置矿机、熔炉、制造台、发电机和矩阵研究站，选择采集目标或设备配方、单选/框选并批量移动卡片，以及从输出端口连接到输入端口。铁矿与铜矿可经过冶炼和组装形成电路、磁线圈，最终在矩阵研究站产出基础研究矩阵。正式建造从施工库存消耗对应建筑件；放置、批量移动、拆除和线路调整由领域命令原子验证，失败不会扣件、丢失缓存物资或留下部分结果。

操作如下：

- `Q` / `W` / `E` / `R` / `T`：分别进入矿机、熔炉、制造台、发电机、矩阵研究站的放置模式。
- 左键：在放置模式确认放置；空闲时选择建筑或线路，Ctrl 点击增减选择，从空白拖动可正向或反向框选，拖动已选建筑会批量移动；在右侧输出端口按下，拖到另一张卡片左侧输入端口并释放以创建连接。空白或 UI 上释放会取消连接并显示原因。
- 右键或中键拖动：平移画布。
- 滚轮：以指针为中心缩放画布。
- `Escape`：有放置、拖动或连接操作时先取消该操作；画布空闲时打开暂停菜单，可立即保存、管理恢复快照或保存并返回主菜单。
- `Delete`：对纯建筑选择打开确认框，确认后原子删除建筑及其连接；混合选择不会静默删除子集。
- `Space`：暂停或继续模拟；`1` / `2` / `3`：切换 1×、2×、3× 模拟速度。

固定 UI 包含顶部状态栏、左侧资源栏、中央画布、右侧检查器、底部建造坞和短时通知。顶部按钮可暂停/继续并切换 1×/2×/3×；资源栏显示持久目标、活动行星托盘、光标载荷、手工队列和生产概况；Inspector 的“任务”入口打开默认收起的战役工作台，可查看目标/成就并定位停工建筑；“科技”入口打开与战役、蓝图和“分析”互斥的正式科技工作台，支持搜索、层级/状态筛选、目录驱动的成本/效果/解锁说明、FIFO 队列、等待原因、暂停/恢复/取消与移出队列。顶栏“星图”入口打开与其他工作区互斥的正式 GalaxyMap：可搜索恒星系、行星和资源，查看距离、资源、殖民成本及工业摘要，并通过领域命令发起勘探、殖民和行星切换；切换会保存来源相机并恢复目标行星相机。顶栏“分析”入口打开同样默认收起的统计、诊断和资料库工作台：统计可按 60/300/600 秒窗口搜索实时生产、消耗、净值与吞吐；诊断显示稳定的停工原因并可定位；资料库查询物品、配方、支持建筑和两层或完整上游链。画布上方的简短教程提示不拦截输入；空闲检查器提供 1～99 的批量手工配方，建筑单选显示设备配置，线路单选显示等级、并联、堆叠、优先级、路线、监控和启停，纯建筑/纯线路多选只显示共同命令；建造坞显示各建筑件的已有/需要数量、旧档兼容额度与缺料原因。失败原因通过不拦截画布的短时通知显示。UI 面板会消费指针输入，中央画布保持可交互。每颗已殖民行星拥有独立库存、建筑、线路、资源储量和相机；固定 tick 会持续模拟非活动行星工厂，活动托盘只是当前行星库存的兼容视图。

连接的 `enabled` 字段表示持久运输许可，`active` 只表示当前模拟帧是否真的发生物流传输；新连接默认启用但在首次运输前不会显示为活动。Mk.I/II/III 额定吞吐分别为 10/20/30 items/s，有效吞吐再乘以 1～4 并联和 1/2/4 堆叠；等级、并联和拆除保持线路施工件守恒。

模拟使用 60 Hz 固定步长，并在单个渲染帧最多追赶 10 个 tick；超出的模拟时间保留到后续帧，不会静默丢失。每个 tick 固定按“电力 → 生产/采集与手工制造 → 线路 → 物流 → 勘探 → 研究边界 → 统计”推进。统计按固定模拟时间采样，历史严格有界，缓存由运行时服务重建且不写入存档。断电会停止生产和物流，欠电按供电倍率减速，恢复供电后保留原进度；手工队列随固定 tick 推进，暂停、保存和加载后可继续。基础熔炉提供当前精简目录的钛合金工业配方，基础处理器可手工制造，因此正式新游戏可以从母星矿产逐步制造物流运输机并建立气态巨星前哨。燃料发电机必须有燃料才能发电；放置时最多把行星托盘中的 10 单位煤转为 300 秒启动燃料，拆除会按剩余燃烧时间返还未用煤。正式补充燃料的交互仍待后续任务接入。太阳能和风能使用可保存的 0～1 发电倍率。

## 行星与星际物流（任务 13）

空闲检查器的手工制造可以制作行星站、星际站施工件与空间翘曲器；同一列表提供两类物流站的建造按钮。星际站放置需要完成星际物流科技。选择一座物流站后点击「配置物流站」，或多选物流站批量配置。

- 每站四个槽位：物品、供应/需求/存储、1～999 容量、1%～100% 最低装载和 0～2 优先级。高优先级优先，同优先级供应源轮转。
- 从当前行星托盘转入真实货物、运输机、飞船与翘曲器；停泊载具可以取回。每次行星内运输最多 20 件，跨行星最多 100 件。两座星际站之间使用飞船；跨星系出发一次消耗 2 枚翘曲器，覆盖往返。
- 槽位可通过正式线路自动进料、出料；检查器可选择线路输出物品。物流送达也计入吞吐统计。
- 断电停止派遣及卸货，已经起飞的载具继续航行；到达后因断电或满载而等待的货物仍归航线所有。需求容量计入在途预留。
- 「停止派遣」允许现有航线继续完成；等待返航后可以修改槽位。有关联航线时禁止拆除；无航线时拆除会预检并返还库存、载具和施工件。
- 累计送达 20 件跨行星货物完成战役目标「完成跨行星材料运输」。航线、停泊载具、槽位、轮转游标和累计送达量均保存；v6→v7 补空物流状态，不赠送载具。

当前手工翘曲器使用基础矩阵 2 + 处理器 2 + 钛合金 2 的阶段性配方，以打通当前精简目录的跨星系运输；完整工业配方和数值仍由后续内容对齐任务承接。手动验收步骤见 [任务 13 验收](docs/current/TASK13_ACCEPTANCE.md)。

## 本地存档

新游戏创建槽位时立即保存；活动会话每 120 秒自动保存，返回菜单和正常关闭窗口前也会保存。每次写入先生成临时档并读回验证，验证成功后才替换主档；上一份有效主档保留为 `.bak`，主档损坏时自动恢复。槽位元数据记录 schema、保存时间、游玩时长、活动行星和规范状态摘要。当前界面没有单独的“立即保存”按钮。

存档默认位于 Godot 的 `user://saves/`。当前 schema v9 保存星区目录、活动行星、探索/殖民状态、每行星库存、建筑、线路、资源储量和相机，以及施工库存、光标载荷、手工队列、目标、奖励领取、本地成就，以及研究当前项、FIFO 队列、进度、已投入矩阵、暂停、队列等待原因、完成科技和可重复科技层数；复制与兼容安装不会共享这些集合。迁移链 v3→v4 补齐研究状态，v4→v5 补齐等待原因并为每个已完成的可重复科技初始化第 1 层，v5→v6 将旧单工厂的建筑、线路、库存和进度无损迁入母星；旧 v2 存档继续先补齐进度字段再按当前工厂事实追溯完成。开始菜单提供继续最近游戏和槽位管理；槽位页提供新游戏、继续、删除确认及返回。损坏档、未知未来版本和不可写目录会停留在菜单并显示可操作原因，不会安装半初始化状态。

## 任务 14：戴森工程

顶栏“戴森”打开正式规划工作区：选择恒星系，创建太阳帆轨道与关联层，按角度添加节点，规划壳面并查看俯视示意、材料缺口和功率估算。界面可选择当前行星发射设备，绑定目标、启停及从托盘装入耗材。三类设备施工件位于手工制造区，解锁戴森工程后使用；太阳帆、组件和火箭的阶段配方由基础制造台生产，线路可自动供帆或供火箭。

太阳帆发射后存活 600 秒；每节点消耗 2 枚火箭获得结构点，壳面至少需要 3 个节点，结构完成后每秒吸附 1 帆、每节点容量 20 帆。接收器共享本恒星系实际戴森功率，并将分配量接入各自行星电网；没有戴森工程时输出为零。规划不赠送材料，已投入结构的层不能直接删除。

schema v8 持久化每恒星系轨道、寿命批次、结构、壳面、发射配置与整数 tick；v7 补空戴森状态。固定步长先处理帆到期，再计算电力，物流之后执行发射与吸附。阶段配方和简化壳面尚非完整 DSPONLINE 内容对齐，任务 15 已接入正式终局胜利。验证与人工步骤见 [任务 14 验收](docs/current/TASK14_ACCEPTANCE.md)。

## 任务 15：单机终局胜利

顶栏“终局”打开星际文明计划。完成戴森工程科技后，将白矩阵 30 和戴森球组件 20 汇入当前行星托盘，并使其恒星系戴森功率达到 3000 kW。确认弹窗列出来源和一次性投入，确认时重新验证条件后原子扣除材料；取消或条件改变不扣除。白矩阵阶段配方位于矩阵研究站，消耗基础矩阵 2、处理器 1、钛合金 1，6 秒产出 1。

启动后绑定来源行星，累计 60 模拟秒合格功率时间后达到单机胜利；低功率与暂停保留进度，切换行星不会借用其他星系功率或改变奖励归属。这里检查实际戴森发电能力，不从行星电网额外扣除 3000 kW。胜利不停止工厂；一次性奖励 10 白矩阵发给来源行星，库存满时保留待领，读档和重复领取不会重复发放。终局工作区展示缺口、功率、速率、预计时间、阻塞和生产定位。

schema v9 持久化阶段、来源、已投入材料、整数进度和领奖标记；v8 迁移为空准备阶段。当前门禁中的 TestDysonEndgame 包含启动原子性、真实白矩阵生产、固定步长、跨行星归属、胜利后运行、文件存档/迁移/损坏拒绝以及正式 UI 确认和定位。该阶段采用精简工业配方，尚未完成完整新游戏人工通关；详细人工步骤见 [任务 15 验收](docs/current/TASK15_ACCEPTANCE.md)。任务 16 已接入安全离线结算与报告。

## 任务 16：安全离线结算与报告

继续槽位时，以已验证存档时间为起点，在独立状态副本上按 1×、60 Hz 精确重放；不足 1 秒直接继续，第一版最多处理 120 秒。计算按帧分段（最多 60 tick / 8 ms，单个 tick 无法中断）；原档在结果提交前保留，工厂输入与自动保存暂不启用。战役事实评估也进入固定 tick，科技、材料、在途物流、太阳帆寿命和终局共用在线模拟规则。

每槽离线事务文件记录起点、目标、摘要及唯一完成标记；结果先持久化，再通过临时档验证与备份轮换提交主档。中断后从原始起点重放或复用已准备结果，重复继续/提交不会再次应用同一时段。回拨不会降低已处理时间边界，超过上限或主动放弃的时间不会在下次继续时补领；旧裸档无可信时间戳时仅建立时间边界。

正式离线工作区显示进度，可放弃尚未进入提交阶段的收益；完成后显示真实离线、实际重放、跳过时间、产出、科技/目标变化与阻塞，写入失败可重试。报告中的产出来自模拟期间的真实统计，不直接添加估算收益。存档和事务文件用完整浮点精度写入，避免长时间累计数值的 JSON 截断导致摘要失败；GameState 保持 schema v9。详见 [任务 16 验收](docs/current/TASK16_ACCEPTANCE.md)。下一项是任务 20 的本地存档控制与恢复体验。

## 任务 17：本机设置与桌面操作

开始菜单和工厂顶栏提供“设置”。主题、80%～200% 字号、紧凑/舒适密度、滚轮缩放方向及手柄光标速度保存到 `user://device_settings.cfg`，不进入存档；切换槽位不影响本机偏好。保存失败保留当前值。保留中文，国际化与手机适配已按用户要求取消。

桌面窗口最小 1000×600，保留顶栏、左右侧栏和建造坞；大字号采用滚动布局，焦点边框随亮/暗主题保持可见。Tab / 方向键导航界面，Enter / 手柄 A 确认，Escape / B 返回。F6 / Y 在界面和画布之间切换；画布方向键 / 左摇杆移动光标，Enter / A 选择或放置，M / 左摇杆按下移动，C / 右摇杆按下连线，Delete / X 请求删除，减号/等号或 LB/RB 缩放，右摇杆平移。鼠标和原有建造快捷键继续可用，删除不会绕过确认。

验收范围见 [任务 17 验收](docs/current/TASK17_ACCEPTANCE.md)。测试入口为每个进程指定独立的 `--device-settings` 文件，避免读写玩家本机偏好。下一项为任务 20 的本地存档控制与恢复体验。

分辨率适配使用当前 Viewport 的可用尺寸，窗口缩放时自动重算，兼容 Godot 已有的窗口拉伸与高 DPI 坐标，不叠加读取主屏幕物理像素而重复缩放。以 1152×648 为参考，按宽高可容纳比例计算自动 UI 比例（85%～400%），再叠加用户字号；侧栏宽度有窗口占比上限，为画布保留空间。顶栏、建造坞、小地图、滚动条和画布命中区域同步更新，自动调整不写回字号偏好，也不改变 GameState。设置页显示当前可用尺寸和自动比例。

## 任务 18：性能监测与本机预算

设置页可开始性能监测，返回工厂操作后停止并导出 JSON / Markdown 报告。默认关闭，每项最多保留最近 3600 个样本；记录固定步、十二个模拟阶段、帧间隔、绘制提交、内存、模拟积压和保存耗时。报告显示实际保存路径，不进入游戏存档。

三档确定性工厂与真实存档读回纳入门禁；图形基准与无窗口测试分开，支持本机趋势比较。已优化传送带排序重复查询、视口裁剪、空间命中和缩小视图批绘，并修复线路整数配置引发的存档摘要错误。实测数据及边界见 [任务 18 验收](docs/current/TASK18_ACCEPTANCE.md)。下一项为任务 20，本地存档控制与恢复体验。

## 任务 19：单机对齐登记

已冻结 DSPONLINE 1.0.46 的实际目录和桌面操作契约，建立 [逐项差距矩阵](docs/CONTENT_PARITY.md)。实际源数据为 78 个物品、80 条配方、39 类建筑、69 项有效科技（另有 7 项弃用定义）、32 个任务和 13 项成就。登记门要求全部条目有映射或缺口、规则规格和任务归属；这不表示原版玩法已经逐项通过。最终发布模式仍按预期拒绝未完成项。用户指定的电脑中文范围继续生效。

## 任务 20：本地保存与恢复

顶栏「立即保存」或 Ctrl+S 保存当前工厂；Escape 打开暂停菜单。开始菜单的存档列表提供「恢复」，可检查并选择主档、最近备份、紧急恢复点和手动快照。恢复旧档需确认，成功保存后才进入工厂，过去的离线时间不重复补算。暂停菜单支持创建快照和管理恢复来源，批量删除会保护最后有效恢复点。详细验证与限制见 [任务 20 验收](docs/current/TASK20_ACCEPTANCE.md)。
